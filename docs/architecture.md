# Architecture and data flow

## Ownership

`MuseConnectionRuntime` owns one process-local LibMuse adapter and retains its native connection across navigation, activity recreation, simulation selection, and session completion. `MainActivity` subscribes to connection state and owns permissions and idle discovery whenever the app is visible, regardless of the selected tab or detail screen. Backgrounding stops idle discovery but preserves an established connection. Manual disconnect, unavailable Bluetooth/permissions, and connection failures can release the adapter. Process termination ends the connection; idle background operation is not a foreground service guarantee.

`MeditationService` subscribes to that same adapter during a live session, without reconnecting an already-connected device. It owns active-session reconnection scanning, timing, audio, processing, and persistence; finishing or destroying the service only removes its subscription. Simulation does not subscribe to live sensor packets or disconnect a connected Muse. Connection/discovery callbacks are serialized on the main thread; packets retain their SDK-thread delivery. Detached consumers and callbacks from a released adapter cannot update the new connection owner. The service remains a foreground service so its timer and audio can continue while the UI is not visible. `SessionRuntime` publishes its current state to the activity; Compose renders that state and sends user commands back to the service.

## Soundscapes

`AmbientAudioEngine` streams bundled Ogg Vorbis recordings through Android `MediaPlayer`, with asynchronous preparation and looping playback. `MainActivity` owns a preview engine; `MeditationService` owns the session engine. Pause/resume preserves playback position, and volume is applied once by the player. Stopping or replacing a track releases its player; a stale preparation callback cannot restart a dismissed preview. No network, synthesis worker, or additional playback dependency is required.

New sessions offer Rain, Ocean, and Fireplace, with Rain selected by default. `MIST` and `TIDE` enum values remain readable with their original history labels; legacy playback commands map them to Rain and Ocean respectively. Existing database rows require no migration. The soundscape sheet scrolls on constrained screens.

The recordings are CC0 field recordings, edited offline for consistent loudness and a blended loop seam. See [audio sources](audio-sources.md) for provenance, processing, sizes, and device validation. Rain includes occasional distant thunder. Loop audibility and headphone balance require listening on the target device; automated checks only establish decoding and playback behavior.

## Live samples

1. `MuseDeviceManager` adapts LibMuse callbacks. LibMuse may call from worker threads.
2. `SignalProcessor` aggregates trusted EEG bands, dynamic acceleration, and estimated PPG heart rate into one `StateSample` per second. Each live band packet is filtered at arrival using fresh per-channel `IS_GOOD` flags; later flags cannot retroactively change accepted data. Only EEG1-EEG4 are considered, and all three bands require a shared trusted channel and a positive sum. Missing or untrusted bands remain null. Sensor activity (`valid`) is separate from EEG availability and Calmness availability (`calmness`). `CalmnessEstimator` owns fixed-reference EEG scoring and smoothing; `HeartRateEstimator` owns a bounded PPG window. Neither processing class uses Android APIs.
3. `SessionSamples` retains the continuous second-by-second sequence, valid count, and last valid sample used for the visual during a gap. If a service tick is delayed across several seconds, it inserts invalid samples for those skipped seconds. The service writes the new rows to `HushDatabase` and publishes the latest state through `SessionRuntime`.
4. At finish, `SessionResultClassifier` uses finite Calmness values for new sessions; fewer than two Calmness values produce no displayed assessment. The service publishes a trend snapshot when new seconds are recorded and a final full snapshot at finish. History and replay read stored per-second values; raw packets are not persisted.

The service uses monotonic elapsed time for timing and checks it every 250 ms while running. A long scheduling delay cannot reconstruct missing sensor windows, so skipped seconds remain explicit data gaps. Long-session timing and collection still require physical-device validation.

Service discovery and connection callbacks are serialized on its main thread; sensor packet aggregation remains synchronized in `SignalProcessor`. Repeated collection-state notifications do not reset windows or smoothing. Debug live sessions keep a bounded private diagnostic trace of packet counts, connection events, and quality filtering, without changing persisted samples. See [EEG gap diagnostics](muse-sdk.md#debugging-eeg-gaps) for interpretation and retrieval.

## Simulation and history

`MuseReplaySource` loads `history/second_earliest_session.json`, the second-earliest recorded device session, through the same `BundledSessionSource` decoder used by history restoration. Simulation requires exactly 600 consecutive samples for seconds 1–600, recorded algorithm versions, usable Calmness, and finite in-range measurements when present. Missing sensor values and invalid seconds remain gaps rather than disabling a structurally complete recording. Loading validates the source and enables the simulation entry; it never imports a saved session into History.

The service reads the source by second through its normal timing, storage, summary, and UI state path when the user starts a simulation. That run creates an ordinary session with its actual date and chosen track. The source preserves original EEG bands, head stillness, PPG-derived heart rate, Calmness, validity, and algorithm versions without rescoring. This recording contains 264 measured heart-rate seconds and 55 EEG/Calmness gaps; missing values remain null. History replay reads persisted samples and positions the shared galaxy using `ReplayCursor`; it does not restore the exact live particle positions.

History supports swiping a card from end to start to request deletion. Confirmation permanently removes the session and all samples in one transaction; cancellation leaves the card available. `MainActivity` performs deletion on its storage executor and refreshes the list only after success. Ordinary deleted sessions are never automatically restored. The second-earliest snapshot remains available for new simulations.

The two earliest completed device sessions are checked in separately as `app/src/main/assets/history/earliest_session.json` and `app/src/main/assets/history/second_earliest_session.json`, including original metadata and all 600 per-second samples each. On the first Activity startup in each app process, its storage executor restores only missing snapshots in a transaction before reading history. Matching original start/end timestamps prevents duplicates, including existing device records with different local IDs. Deleting these two records works normally for the rest of that process; a cold restart restores them. Activity recreation and ordinary history refreshes do not restore deletions. Simulation loading itself does not restore history, change the database schema, clear other history, or recalculate recorded Calmness. The temporary raw device database exports are removed after verification; only the selected two sessions are bundled.

## UI and rendering

`SessionDuration` defines the 10-minute default and 1-60 minute live-session range shared by Home, Activity state restoration, and foreground-service validation. The single inline Home wheel displays minutes as `MM:00` and updates the selected duration in seconds as its centered minute changes, using the existing session handoff. Simulation resets and disables the wheel and continues to use its fixed 600-second source duration. `SessionPreparationPanel` renders the setup card; the Home header music button opens the existing soundscape sheet, and the card's connection status opens the device sheet. These controls do not own audio, Muse connections, or persistence.

The UI consumes processed `SessionState` and `StateSample` values. `GalaxyParticleField` and `GalaxyMotion` own the visual mapping and animation; composables do not receive raw LibMuse packets or write session samples. See [design system](design-system.md) for screen conventions and [README](../README.md) for build and device validation commands.

`SessionState.eegStatus` is transient and distinguishes available, low-quality, interference, unknown-quality, and missing EEG. It comes from the processor (or trusted simulation samples), independently of Bluetooth connection state. Live EEG gaps keep the galaxy drifting at its retained visual parameters and reduced opacity, without producing Calmness; valid motion and heart-rate measurements remain available independently. Before any trusted Calmness value exists the drift is decorative. Pause stops the frame loop; recorded replay gaps retain their original frozen shape.

## Validation boundary

`./gradlew.bat test` covers the JVM processing, replay, session-sample, auto-connect, and deterministic-motion tests. Compose and service integration checks run through `:app:connectedDebugAndroidTest` on a configured device. Neither automated suite proves Muse Bluetooth reliability, long-session timing, background reconnection, audio behavior under lock screen, or frame pacing; those require a physical Android device and Muse 2.

## Demo signal processing

Algorithm version 5 scores the first trusted EEG second without personal calibration. EEG uses `x = log((alpha + theta + 0.000001) / (beta + 0.000001))` and `sigmoid(clamp((x-b)/s, -30, 30))`, with fixed `b = 0.76507906870225273` and `s = 0.32801364656479376`. The parameters are subject-balanced over 10 CogWear pilot baseline recordings, with participant 3 explicitly excluded because its baseline EEG is unpublished. A feature equal to `b` maps to 50 before temporal smoothing; this is a typical resting reference, not a measured neutral or calm mental state. See [reference extraction](eeg-reference-dataset.md) for conversion, filtering, and reproducibility. Live and offline reference extraction average each channel within a second before averaging the shared usable channels with equal weights. Finite 0-1 values are required. Live channels additionally require `IS_GOOD == 1` at packet arrival with a nonnegative age of at most two seconds. Fresh finite `HSI_PRECISION` values in (2, 4] reject the channel even if `IS_GOOD` is 1. Values in [1, 2] identify usable fit but never override an artifact flag: `IS_GOOD == 0` still rejects the measurement and is classified as interference when fit is usable. This does not identify the specific artifact or reconstruct clean EEG. Missing, expired, nonfinite, or other quality values remain unknown. Without usable fit information, zero retains the low-quality fallback. Only trusted EEG contributes to Calmness. A zero flag does not prove bad electrode contact or Bluetooth failure. Simulation bypasses live quality checks by replaying the already-processed recording, including its recorded gaps.

Acceleration removes a low-pass gravity estimate (one-second time constant), then maps per-second dynamic RMS to `exp(-RMS / 0.05g)`. PPG reads simultaneous IR/Red channels, uses an eight-second nominal-64Hz window with 0.7-3Hz filtering and refractory peak detection, and rejects flat, inconsistent, stale, explicitly poor-quality, or implausibly sampled windows. Demo BPM support is 40-180. Heart rate is estimated independently, without a personal heart baseline or EEG requirement. No HRV is calculated.

Calmness uses only the sigmoid-normalized EEG feature and is smoothed with coefficient 0.2 per valid second; the UI maps galaxy agitation to `u * (0.5 + 0.5 * u)`, where `u = 1 - calmness` to moderate resting and calm motion while retaining visible score differences. Live rotation uses `0.06 + agitation * 0.17` radians per second after visual smoothing. This changes rendering only, not stored scores or the processing algorithm version. Heart rate and acceleration do not enter Calmness or galaxy agitation. Acceleration independently measures head stillness and supplies the Stability summary. These thresholds are engineering heuristics, not a validated meditation-quality or medical assessment. Artifact rejection uses the SDK's rolling `IS_GOOD` flags; no blink, jaw-clench, or headband-wear event subscription is required.

Pause and disconnect reject new sensor data and clear short windows, while retaining EEG band and Calmness smoothing. Low-quality and missing seconds do not update smoothing. Repeated notifications of an unchanged collection state leave smoothing and sensor windows intact. A new session resets all processing state. Live animation continues without updating its physiological parameters during unavailable Calmness data, while charts mark missing intervals with decorative dashed bridges.

## Storage and algorithm versions

Database version 4 introduced nullable `heart_rate_bpm` and `calmness`, plus `algorithm_version`. Version 5 retains the same columns but intentionally resets all prior history: `SQLiteOpenHelper` upgrades in a transaction, deleting samples before sessions, including unfinished rows and the reserved auto-imported simulation. Versions 1-3 first receive the existing column upgrades. This reset runs once; fresh installations start empty, and subsequent launches preserve new sessions. Preferences and non-session files are unchanged. Automatic simulation import and backfill have been removed.

Algorithm version 4 removes heart-rate fusion from Calmness. Live samples store the EEG-only Calmness that drives the galaxy and chart; simulation retains the source recording's Calmness and algorithm version. Quality rules introduced in versions 2-3 remain: packet-time EEG quality filtering, poor-fit rejection, and separation of interference from unknown or low quality. That database migration predates algorithm version 5. The current scoring change does not upgrade the database, clear history, or recalculate stored scores. Algorithm version 5 replaces personal calibration with the fixed public resting reference; existing version-4 samples retain their recorded values. No calibration progress is published in session state or diagnostics.

## Experimental session metrics

`SessionScoreCalculator` is a pure Kotlin summary calculator. At finish the service computes `SessionScores` from the complete processed sample list and publishes it with the trend snapshot. Detail screens use the same calculator over persisted samples. `SessionScores` contains only nullable `calm`, `stability`, and `heartRateBpm`; summary values are derived, not stored. History loading uses the same calculator on the storage executor and includes nullable `SessionSummary.calm`, keeping list values consistent with session details.

Rows with `algorithmVersion == 0` or `valid == false` are excluded. Each dimension independently filters finite measurements and requires at least 30 measured seconds, which need not be consecutive. Calm is mean Calmness in [0, 1] multiplied by 100. Stability is mean stillness in [0, 1] multiplied by 100 and reflects head motion, not whole-body motion or Calmness variance. Heart Rate is mean measured BPM in [40, 180], not a score or HRV. EEG gaps do not disqualify valid motion or heart-rate measurements. Missing measurements are excluded, never interpolated, scored as zero, or penalized.

Completion and detail show `Calm`, `Stability`, and `Heart Rate` in that order. Numbers are rounded only for display; Heart Rate includes `BPM`. Unavailable metrics display `—`. Focus and overall grades have been removed. Simulations use the same path and never invent heart rate.

`EegNoticeTracker` is a service-owned presentation policy. `SessionState.eegStatus` remains the immediate processor result; nullable `eegNotice` gates the main warning after 20 consecutive unavailable sampled seconds. Before a notice appears, any available second restarts that grace period; intermittent losses cannot accumulate indefinitely. After a notice appears, two consecutive available seconds clear it. An ongoing notice follows the current unavailable condition so restored contact cannot leave a stale low-quality warning during interference (`Signal settling…`). Missing timer seconds interrupt recovery. Repeated updates for the same second are ignored. Pause, disconnect, and new sessions reset it. The policy leaves processing, persisted samples, charts, and scores unchanged.

Charts draw smooth solid curves between consecutive trusted samples and subdued dashed curves across unavailable intervals. A live trailing gap holds the last trusted level as a dashed guide until a new trusted value arrives. These guides exist only in Canvas drawing; stored null values, scoring, and replay samples are unchanged.
